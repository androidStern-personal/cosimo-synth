# Shared audio data

Your preparation function writes the allocation that DSP will read. The framework owns allocation, cancellation, the audio-block switch, and releasing replaced data. Native JIT, compiled native and browser WebAssembly use the same author declaration.

```ts
// PLUGIN AUTHOR: state.ts. Preparation runs outside audio processing.
import { definePluginState, preparedState, sharedData } from "../../kit/index";
import { curveCodec, initialCurve, renderInto } from "./curve";

export default definePluginState({
    envelope: preparedState({
        codec: curveCodec,
        initial: initialCurve,
        engine: sharedData({ type: "float32", length: 2048 }),
        prepare(curve, destination) {
            renderInto(curve, destination); // Writes final shared Float32Array.
        },
    }),
}, { memoryBudgetBytes: 64 * 1024 });
```

Use `Mseg.state()` for the bundled curve codec, renderer and 2,051-sample padded representation. For a known fixed size, supply numeric `length`. When loading or measuring data first, omit `length` and return a preparation plan as below. Float32 lengths count samples. `type:"bytes"` lengths count bytes and must be multiples of four.

The writer is synchronous and must not retain or mutate its destination after returning. It may return `preparationFailure(message)` before publication. This keeps cancelled storage safe to reclaim; source loading can happen before the write. An advanced delivery can use document-scoped `prepareData` when it needs a longer-running protocol. There is no second full prepared buffer and no sample data in upload messages.

## Load once, then write

```ts
// PLUGIN AUTHOR: this callback runs outside audio processing.
// The framework supplies the same resource reader in native and browser builds.
preparedState({
    codec: sampleFileCodec,
    initial: "sample.wav",
    engine: sharedData({ type: "float32" }),
    async prepare(file, { resources }) {
        const audio = await resources.readAudio(file);
        const channel = audio.samples;
        return {
            length: channel.length,
            write(destination) {
                // Or perform your own conversion directly into destination.
                destination.set(channel);
            },
        };
    },
});
```

`resources` is the existing kit resource client (`readText`, `readBytes`, `readAudio`). Loading may be asynchronous; the final writer is synchronous. The loaded source belongs to this operation's closure, not an author-managed shared cache. The framework measures the plan, reserves final storage, calls its writer and publishes only when complete. A superseded load cannot write or publish after finishing late. Return `preparationFailure(...)` for a recoverable loading error; an unexpected throw becomes a non-retryable field error.

The old `sharedData({input})` completed-buffer overload and `replaceData` upload helper were removed. New declarations have one direct-memory behavior. A specialized component can still select an explicit `PluginStateDelivery`; the older `engineData` protocol remains explicit for DSP components that actually use it.

## Size and DSP access

The normal build generates named references from the declaration:

```cmajor
// PLUGIN AUTHOR: inside DSP. Generated by the build, not handwritten endpoints.
let count = PluginState::envelope::size();
float sample = PluginState::envelope::read(sampleIndex);
```

For bytes, `size()` counts 32-bit words and `readInt(wordIndex)` reads an integer word. The component author owns layout and interpretation. `kit/cmajor/mseg.cmajor` supplies a ready MSEG reader/player; it keeps playback position, triggering and looping per instance while reading shared curve samples.

The author supplies one `memoryBudgetBytes` ceiling across the declared resources. Fixed lengths are known at build time; variable lengths are measured per preparation. The framework allocates on demand, not one full budget per field. The ceiling must accommodate currently playing data plus unpublished replacements. Refusal preserves the current audio and exposes a retryable field error. Browser memory may retain its high-water capacity until the program closes; fragmentation may prevent a contiguous allocation.

One complete replacement becomes visible at the start of an audio block. Readers in that block see a stable version. Replaced allocations are reclaimed after audio finishes reading them. No audio-thread allocation, deletion, locks or waits are required. This default is not per-note retention of historical versions.

## Typed native settings

```ts
// PLUGIN AUTHOR: part of definePluginState(...).
settings: nativeValue({
    codec: Native.record({
        enabled: Native.boolean(),
        amount: Native.number({ min: 0, max: 2 }),
        mode: Native.choice(["clean", "warm"]),
    }),
    initial: { enabled: true, amount: 1, mode: "clean" },
})
```

```cpp
// PLUGIN AUTHOR: native component, called during audio processing.
#include "PluginState.h" // Generated matching types, defaults and validation.
const auto settings = PluginState::settings.readForAudioBlock();
if (settings.enabled)
    output *= settings.amount;
```

There is no callback unless your own processing needs one: read the current typed value where you use it. The getter returns the complete validated setting for that block, or its declared default if no valid resource is available. A value sitting in memory does not itself change sound; the component must use it. `Native` supports finite float32, boolean, named choices and fixed nested records (up to 256 words). Field and choice names must be valid non-reserved native identifiers. General arrays/audio assets use `preparedState` instead.

The generated native helper uses the framework audio read scope. A specialized browser C++/Wasm component must attach the corresponding Wasm block reader to the host's block boundaries; `PluginState.h` selects that reader when compiled to Wasm. Plain Cmajor readers are connected by the kit host.

## Status and compatibility

Acceptance means the editable value/history changed. `control.state.application.kind === "acknowledged"` additionally proves audio adopted that exact replacement. Saving or delivery errors do not discard the accepted edit. The hook exposes `error` and nullable `retry`; retries cannot reinstate an obsolete target.

This requires the patched Cmajor shared-data runtime, including direct writable reservations and audio-adoption receipts. Browser hosts need cross-origin isolation and shared WebAssembly memory. An unsupported host fails visibly; this implementation does not silently fall back to the older packet path. Native and browser storage differ internally; author preparation and state APIs stay the same.
