# One-command customer installation

The delivery line owns the prefilled destination, existing access credential
and explicit JUCE acknowledgment. It does not accept Apple agreements or start
plugin work. A Bash boundary is necessary because a clean supported Mac may
not have Node. It reuses the existing release lineage, tool pins, setup and
doctor contracts; it is not another authentication or package-manager system.

The download pipeline buffers its body, requires a completion trailer emitted
only after curl succeeds, and checks the exact supplied SHA-256 before running
it. `pipefail` alone would still allow a complete-looking failed transfer to
execute and print success. Git uses an environment-only remote, disables
interactive credentials and inherited trace sinks, and checks the exact
release commit before checkout. Curl ignores user configuration on this path.
The underlying feed's existing capability storage contract is unchanged.

Node and CMake use project-local pinned official archives, never system
installation or shell-profile changes. A shipped root instruction activates
the installer environment for each new agent shell. This deliberately trades
machine-wide convenience for project isolation. Existing old exports without
that instruction cannot pass the new entry flow. The official checksum lists
are [Node 22.23.2](https://nodejs.org/dist/v22.23.2/SHASUMS256.txt) and
[CMake 4.3.4](https://github.com/Kitware/CMake/releases/download/v4.3.4/cmake-4.3.4-SHA-256.txt).
Updating runtime pins requires maintainer review and fresh-runtime proof.

Reruns recognize one small installer receipt, not an ownership registry. Only
the original empty/unborn acquisition may create the customer branch; existing
customer history and work are never reset. A completed npm receipt avoids
mistaking a partial `node_modules` directory for a successful lifecycle run.
Installer control paths cannot be symlink redirections. Reused runtime payloads
are checked for names, modes, file-byte hashes and symlink targets before they
execute, using system Perl/Digest::SHA (available with macOS's `shasum`). An
archive receipt or a version string alone cannot establish payload integrity.
Questionable runtime paths or an interrupted lock stop for inspection rather
than overwriting data. Runtime directories and caches are disposable output;
the installer does not clean other caches, projects or installed plugins.

Rerunning an old delivery also refuses changed `kit/` implementation files,
including a newer kit update. Executing different setup code under an old
delivery's pins would weaken the verified-release claim. Customer changes in
`fx/` and root files remain intact; changing/updating the kit requires a matching
delivery or the existing update workflow, not an automatic reset.

Focused tests execute the emitted line through actual HTTP, Git, archive,
npm-lifecycle, setup and doctor boundaries. Their tiny substitute runtime
archives are not evidence that a clean Mac can download and execute the
official runtimes. That separate gate uses a committed composed customer
export in a disposable supported environment, with its own real downloads and
fresh cache. An unpublished loopback candidate remains unpublished; neither
qualification proves DAW discovery, UI, audio or licensing eligibility.
