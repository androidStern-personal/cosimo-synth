## Source review findings, September 5

Real browser key input exposed an inherited dispatch-timing defect that synthetic `dispatchEvent` checks missed: a microtask scheduled in window capture can run before target/plugin handlers. The first numeric-only candidate therefore forwarded Space even when a number field subsequently called `preventDefault()`. A bare next-task decision fixed ownership but allowed a real button's default activation as well as host forwarding, so it was rejected. The reviewed direction appends an event-specific window-bubble listener after already-registered plugin handlers and cancels browser default before dispatch finishes. Stopped propagation initially fell back to discard; root review requires preserving a matching host key release when only key-up is stopped. Native queue lifetime and original-event forwarding remain unchanged. Dynamically registering a new window listener during capture is a known ordering limit requiring explicit review, not an unqualified claim that every possible handler runs first.

The generator's literal UTF-8 name fix exposes a separate JUCE factory3 bug. Pinned JUCE `501c07674e1ad693085a7e7c398f205c2677f5da` builds `PClassInfoW` using `infoW.fromAscii(info2)`, which widens UTF-8 bytes instead of decoding them. Narrow factory names are correct while non-ASCII wide names are corrupt. The existing identity probe only checks the narrow processor class and cannot qualify this boundary; a temporary actual-binary probe now reads factory1/2/3 names and both processor/controller IDs without creating plugin instances.

A six-line owning-layer JUCE patch using the SDK's existing UTF-8-to-UTF-16 converter has been prepared outside Git and compiled against the pinned SDK. ASCII, BMP and supplementary Unicode names pass with unchanged narrow bytes and both tested IDs. The exact patch and negative/positive proof are in the evidence directory's `unicode-factory-seam/`. No JUCE checkout/cache was modified and no new fork was created.
