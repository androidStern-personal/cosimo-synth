That is useful prior art, not a ready Undo engine: rack state is not in the synth preset adapter list, preset application is a full load rather than an edit transaction, and complete rollback across a failed multi-domain apply is not currently guaranteed.
    - Two isolated recovery mechanisms exist and must not become competing histories: the MSEG editor holds one previous shape, while Articulations temporarily remembers one discarded edit. No global stack, Redo stack, or cross-domain compound action exists.
    - Desktop host-keyboard routing already provides the required ownership seam: the native CHOC layer temporarily retains the original key event, ordinary UI code handles a normal browser event, and `preventDefault()` tells the bridge that Cosimo claimed it; unclaimed musical-typing/transport keys can still be returned to the host. Implement Undo through that one existing route. Do not add a second native interception path, call host-forwarding APIs from product components, use `[NSApp currentEvent]`, or resign the WebView as first responder.
    - The investigation compared per-action before/after records, complete sound snapshots, and a hybrid approach. It rejected repeated whole-sound/document snapshots and selected owner-encoded logical fragments because they preserve the existing state authorities, avoid presentation-state capture, and give large structured edits a bounded representation.
    Chosen architecture (2026-08-20):
    - One transient native history belongs to the running synth/plugin instance, survives editor closure, and is never serialized. The existing parameter, table, rack, modulation, and articulation owners remain authoritative.
    - Each complete user action records only the accepted before/after fragments that changed. Explicit action tokens replace the current anonymous gesture grouping, so a rolling-axis drag remains one Undo step.
    - Undo and Redo stage every affected owner's candidate and publish the complete result together at one audio-block boundary or publish none. Routine Undo never invokes the voice/effect-resetting cold-restore path.
    - Host changes use owner generations to win or invalidate conflicting history predictably. Successful full-sound replacement starts a new epoch and clears both stacks; failed replacement preserves them.
    - History capacity is chosen from measured bytes after imposing a finite accepted MSEG payload bound. Capacity pressure may reject a new action before it starts, but an admitted valid edit may not become an untracked partial action.
    - Public Undo/Redo remains hidden until every enabled user sound-write path is correlated, source deletion is canonicalized or disabled, private MSEG/Articulation recovery ownership is removed, and the full acceptance suite passes.
    Done when:
    - The user-visible scope, grouping, and lifetime rules are explicit.
    - Undo restores both the sound and every affected visible control to the prior user-visible state.
    - Desktop integration tests prove that focused Cosimo handles its Undo shortcut exactly once and does not leak it to the DAW, text fields retain normal typing Undo, and unclaimed musical-typing and transport keys still reach the host with matching key-down/key-up behavior.

    - Define intentional behavior for ambiguous modulation amounts instead of treating every number as an unexplained raw scalar.
    - Every exact-value field visibly states its default unit. A bare number uses that displayed default; a compatible unit typed with the number may override it. For example, a Cutoff field whose default is Hz treats `2000` and `2 kHz` as the same value.
    - For the base filter Cutoff, accept Hz, kHz, and percentage. Percentage means the position through the existing logarithmic 20 Hz–20 kHz Cutoff range: 0% = 20 Hz, 50% is approximately 632 Hz, and 100% = 20 kHz; it does not mean a linear percentage of 20 kHz.

    Current technical reality:
    - Unit-aware parsing already exists in separate places: Cutoff accepts Hz/kHz, envelope time accepts milliseconds/seconds, and rack controls accept their displayed units. The rules are duplicated and incomplete.
    - A route does not store one universal percentage. Its numeric `amount` is interpreted by its target: normalized targets use a -1..+1 offset displayed as percentage, pitch uses semitones, level uses dB, envelope/MSEG timing uses seconds, and logarithmic targets such as Cutoff, Delay Time, and Phaser Rate use octaves. A UI percentage such as "50% depth" is derived from that target's allowed amount; it is not the persisted route value.
    - Exact entry must translate compatible typed units into that existing target-owned amount. It must not replace the canonical route amount with a second percentage representation. For example, entering a Delay endpoint change from 250 ms to 500 ms resolves to the existing +1-octave amount and therefore remains a 2x interval if the base time later changes.

    - This ticket specifies input behavior, not the parser/storage design. Before implementation, inventory the existing per-surface rules, discuss the appropriate shared architecture, and record that design separately.
    - As part of that inventory, assign each parameter family its obvious displayed default and common compatible typed units. Use ordinary domain meaning without requiring product review for every conversion; return only genuinely ambiguous cases for a product decision.
