Loop-synced Auto-preview retriggers (T12B) — 2026-08-19
- Physical finding from the first minutes of phone use: mid-cycle retriggers chop a looping MSEG's rhythm. Fix: a pure strike-time quantizer (ui/shared/auto-preview-sync.ts) between the scheduler's command and the note layer's strike — the scheduler still owns WHEN a strike is due; the quantizer slides it (bounded: 150 ms leading / 300 ms otherwise) onto the loop grid of the SLOWEST looping MSEG that modulates anything (user decision: unmapped MSEGs ignored, salience + shared-anchor harmonics make slowest the right pick).
- Load-bearing engine facts: MSEG rate is seconds-only (no tempo sync exists; the BPM gate is moot); the loop is a sub-region so T = (endX - startX) * rate.seconds; MSEGs run per voice and restart at note-on (effectiveMsegState reports the newest audible voice), so the loop phase is anchored at a note-on JS itself observed — the sync is pure arithmetic from lastNoteOn + k*grid, and playhead telemetry is not needed for v1 (kill-switch cross-check deferred to tuning).
- Gotcha (emit chain): a new ui/shared module imported by ui/shared/modulation.ts must be registered in ui/build.mjs's patch_gui emit list, or the next build breaks the generated modulation.js import chain (tests import patch_gui/*.js directly). user-edit-bus.js is registered now.
- Invariant worth keeping: every auto-preview cancel path clears the deferred strike EXPLICITLY before the engine dispatch, so an endPreview command arriving with a strike still pending always means "release" — the pending hold strike converts to the capped final note and the last value is heard on the beat.
