# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable decisions for this prototype

- This is a parallel React/Vite product prototype for Cosimo's eventual iOS UI, not a disposable HTML mock and not the production integration itself. Keep product components independent from mock data so `CosimoMobileExperience` can later receive a real iOS/Cmajor adapter.
- Keep the presentation as a plain structural wireframe: white canvas, black outlines, native controls, no decorative visual styling.
- The persistent shell includes the patch header, ordered effect rack, unified source rail, current articulation, and audition/capture controls.
- In an effect view, the primary effect stays visible above the persistent source rail; do not cover effect parameters with a drawer.
- The source rail is the single persistent modulation surface. A chip tap explicitly changes focus to the source editor; a vertical scrub on a lit chip doses that mapping in place while the primary module stays visible. There is no separate mapping-chip row or relationship-detail band.
- Global effects are patch-owned. The articulation selector remains available for audition, but it does not create a Phaser base-value override.
- Voice/Oscillator and Effects Rack are sibling sound-design workspaces selected from the centered persistent header control. The Voice workspace exposes Wavetable, Voice Filter, and Amp/Pan as its module strip.
- Scalar parameter tiles are the controls: tap selects, horizontal drag edits the base value, and vertical drag edits the focused mapping's amount. Do not add a redundant permanent large slider above them.
- Every scalar tile visually identifies the base position, patch-default tick, selected modulation range, and selected source. Exact numeric values appear transiently during manipulation.
- Persistent compound settings such as Free/Sync and rhythmic division live as compact overlays inside the module graphic. They remain visible regardless of parameter selection so the editor never shifts vertically.
- Source-rail chips use compact type icons plus slot numbers. Source-editor target rows must contain the same editable parameter control, show the actual targets for the selected source, own polarity/reducer/remove, and offer an explicit action that opens the target module with that relationship selected.
- Returning from a source editor restores the module that opened it. Never hard-code the return target to Phaser.
- Do not add explanatory captions such as `Ordered effects — scroll` or `Sources — tap to edit`; the visible controls must communicate their own purpose.
- The persistent workspace selector is an icon carousel, not a dropdown: the current workspace is the large center icon, smaller previous/next icons remain visible, tapping a neighbor changes workspace, and horizontal swiping changes workspace. The third workspace is Articulations (decided 2026-07-18); the carousel carries Voice, Effects, and Articulations.
- The rail is a fixed 7×2 grid sized to full source capacity (4 macros + 3 envelopes + 3 MSEGs + 3 fixed + Add = 14 slots) and NEVER scrolls — with no pan gesture, a drag on an unlit chip assigns in any direction, and a horizontal drag on a lit chip is deliberately inert. Empty slots stay silent. Do not create a separate title/action row or show an instructional empty-state card when no mapping exists. The vertical room came from the rack (96→80) and the flexing module graphic, which were oversized.
- No relationship heading: the selected parameter is already visually obvious. Lit rail chips display their amounts and support vertical drag for quick amount adjustment.
- Remove `Expand` until a concrete deeper relationship-editing use case exists. The prior expanded state duplicated the compact card and therefore did not earn its space.
- Module graphics must be real, live line-art visualizations driven by the current parameter values, with the existing touch surface layered over them. Do not fill the area with instructional placeholder text.
- Fixed performance sources (Velocity, Pressure, Slide) are permanent rail citizens with distinct identity icons: they assign, scrub, and take per-parameter remove like any source, but they have no editor (tap is a quiet no-op) and can never be deleted.
- Icons come from fontaudio (https://github.com/fefanto/fontaudio), decided 2026-07-18. It is an audio-specific icon set (envelopes, waveforms, filters, modulation, keyboard) — use it for instrument identities instead of hand-drawing glyphs, generating them, or stretching generic UI sets; Phosphor remains acceptable only for generic UI verbs (add, close, carets, navigation). fontaudio has no npm package: vendor its webfont/SVG assets into the repo. Licenses: icons CC BY 4.0 (attribution required — add it to CREDITS.md when vendored), fonts OFL 1.1, code MIT. This choice is pragmatic, not final art direction; a bespoke family may replace it later, so keep icon usage routed through `IdentityMark.jsx` where a swap stays a leaf change.
- Every effect-rack tile exposes an editable quick control for that effect's last-touched parameter. Rack order is already visible spatially, so do not show ordinal numbers.
- Long-pressing a rail chip opens its compact action menu. Lit chips expose the mapping's settings — polarity toggle, Enable/Disable, and Remove from the selected parameter (fixed sources included); user-created sources additionally expose Delete, which removes the source and all of its mappings. Reuse the first available slot when another source of that type is added later.
- Every continuous control must feed the shared transient heads-up value readout while it is manipulated, including rack quick controls, mapping amounts, and source-editor sliders — EXCEPT controls that are their own always-visible value home and would be covered by the HUD (the articulation lane's keyswitch handle and MIN/MAX bound fields). A value appears in exactly one place at a time.
- Preserve the black-on-white wireframe as the base language. Color is semantic and reserved for articulations and modulation sources. Each articulation and each source slot gets a stable unique color inspired by Native Instruments Super 8 and XLN DB-30 Drum Butter; reuse that color everywhere the identity appears.
- Each articulation has a compact icon. Only parameters with a sparse articulation override show that articulation's icon and color; the reset lives as the override chip in the module-editor header's reserved context slot and clears that target's base-value and route-amount overrides together.
- Articulation flow (decided 2026-07-18, from the interactive models): overrides are authored ONLY inside the explicit worn edit layer — the audition articulation never silently reroutes edits (this deletes the old invisible mode). The transport's articulation control gains an EDIT latch on non-Default selections; wearing snapshots the layer and exit returns to wherever wear began (✓ commits, ✕ restores the snapshot). While worn, per-note voice edits write the articulation's sparse override; global effects remain patch-base even worn.
- Worn-mode chrome (revised 2026-07-18 after hands-on review): wearing is MODAL and its chrome is total — the frame wraps the entire shell in the articulation's color on every screen, and the articulation tab (icon, name, ✓, ✕) replaces the system menu in the header, flush with the top edge with a contoured bottom, returning the menu on exit. Two grammar rules are reserved exclusively for this mode indicator so it can never be mistaken for a boxed control: solid colored fill, and the tab contour radius (`--cosimo-worn-tab-radius`, the single sanctioned exception to the 2px radius rule). The module header never hosts mode chrome — its context slot belongs to the override-reset chip and navigation returns only.
- The Articulations workspace hosts the bank and its tools: articulation cards in the rack region (color, name, SEL selector number, active-mode assignment, override count; hold-▶ previews through audition; long-press Duplicate/Delete; Add mints the next slot/selector), a trigger lane below (Key: display-only ~1.5-octave piano with octave paddles plus a separate labeled drag handle and ∓1 nudges so the finger never occludes placement — keyswitch movement clamps flush against neighbors with a haptic at first contact, and markers carry no text since color is the identity and the handle names it; Vel/Chain: partition strips with tap-select and scrubbed MIN/MAX where ranges never overlap — a dragged bound stops flush at the neighbor's edge with the same haptic, so growing requires shrinking the neighbor first; play-to-set only ever appears with MIDI input), and the selected articulation's diff: full-width touch rows whose whole surface is the control (track with base tick + handle, struck base beside live value, full-height remove), with the row name navigating to the target module (selected + flashing) and a Back action returning to the workspace. The transport articulation strip renders on this workspace exactly as on every other (reversed 2026-07-18: one identical strip everywhere beats contextual removal). Lane controls are their own value homes — no HUD readout may cover the lane. The user-facing verb for entering the edit layer is EDIT ("Edit Pluck"), never "wear" (which remains internal vocabulary only).
- Deferred articulation items (do not mistake for omissions): slot rename; per-articulation envelope/MSEG-morph overrides (engine parity gap); card snapshot thumbnails (they visualize that missing data); play-to-set assignment.
- Rail chips remain compact and directly adjustable in place; the deep source editor is entered through an explicit chip tap or a source-editor target action. Source-editor targets remain compact until one target's relationship settings are selected.
- Modulation reducers are contextual: show Mean/Max only when a per-note or MPE source crosses into a global target. The reducer is a deliberate divergence from the current engine (whose mod matrix has no global-effect targets); this design takes precedence and is the intended engine addition.
- Mod-matrix semantics follow the real synth (`ui/shared/modulation.ts`, `cmajor/FixedFrameOscillator.cmajor`): sources emit 0..1; polarity transforms the source (unipolar keeps 0..1 and pushes one way from base, bipolar remaps to −1..+1 and swings around base — its band straddles the base on every track); inversion is the sign of the amount, never a separate flag; amounts are signed values in the target's own units (frequency ±6 oct, semitone ±48 st, amp level −48..+6 dB, pan L/R, percent elsewhere) with +X/−X unipolar and ±X bipolar readouts; unipolar is the default for every source (nothing in Cosimo rests mid-travel); every mapping has an enabled flag distinct from removal (disabled stays lit with a struck amount and a ghosted band); a new mapping defaults to 25% of its target's magnitude limit.
- Articulations override route amounts, mirroring the engine's per-articulation routeAmounts: with a non-Default articulation active, editing a per-note voice mapping's amount writes that articulation's sparse override; global effect mappings stay patch-base. Reset clears a target's route-amount overrides along with its base-value override. RESOLVED (2026-07-18): an articulation-override amount announces itself on the parameter cell the same way a base override does — the articulation mark appears in the cell heading, and the Y amount value renders in the articulation color (the band itself stays source-colored; color on the value, not the geometry, avoids fighting source identity). While wearing an articulation, edits to global (effects) targets land on the patch base and the HUD readout appends “GLOBAL — EDITS PATCH BASE” so the silence of the cell is explained at the moment of touch.
- Source-rail chips show an upper-right target-count badge. Rail dimming is scoped to the selected parameter: chips not attached to it recede, and global orphan-ness shows only in the badge. Source chips drag onto visible eligible parameters; beginning a drag shows a ghost chip that follows the pointer, exposes drop targets, and a successful drop creates or focuses the mapping.
- Opening a target from a source editor creates a shallow return path back to that source, restoring target focus and scroll position.
- The retrospective motion buffer belongs to the parameter moved while a MIDI note or the on-screen Trigger is held. Capture must not retarget the motion based on whatever is selected afterward.
- Effect-rack reordering uses a distinct drag handle, not the tile body or quick-control track. Rack quick controls reuse the same small black wireframe range language as other continuous controls.
- Source editor controls use real port units (amended 2026-07-19, replacing the prior graphic-only envelope decision): Macro is normalized 0..1 and displayed as percent; Envelope has logarithmic Attack/Decay/Release scrub rows in seconds plus Sustain percent and a real ADSR plot; MSEG uses the shared editable A/B shapes with morph, seconds, loop, and touch hold-or-drag segment bending.
- Primary scalar controls share one borderless parameter matrix. Preserve large invisible touch cells, but let alignment, whitespace, typography, and one outer calibration-panel boundary provide the grouping instead of drawing six separate cards.
- Contextual mappings render as lit chip states on the persistent rail in the normal module view. Source colors are small identity marks on the chips; the focused mapping's chip carries a corner-tick calibration frame, never a black/white inversion. Deeper settings belong to the source editor's target rows, not an inline band or expanding card.
- The persistent source rail reads as a graph legend, not a row of colored cards: controls are borderless chips inset with small margins, identity color is confined to the glyph and short underline, attachment count stays raised, and the focused source gets a corner-tick frame — never an inverted slab that fills its slot.
- The persistent audition area is an anchored transport footer. Articulation, note, and Trigger are stable grouped controls; categorical selections may use black/white inversion, while Repeat, Latch, Capture, and buffer status form a quieter secondary row.
- Treat the selected Ulm scientific-instrument mock as directional visual truth for hierarchy, density, typography, and active states, while preserving Cosimo-specific interactions rather than cloning the mock mechanically.
- The effects rack is one continuous horizontal instrument surface with light internal dividers, not a row of independent bordered cards. The active effect inverts black/white. Module focus, last-touched quick scrub, enabled state, and reorder handle must remain visually and gesturally distinct.
- Use the checked-in IBM Plex Sans Condensed font for display/control labels and Departure Mono for values, units, transient HUD text, and compact status. Do not render visible UI text below 10px.
- Use a four-level rule hierarchy: dark major workspace boundaries, light internal hairlines, strong active focus, and 3px semantic source/articulation rails. Avoid nested full-black rectangles and equal-weight borders.
- One tiny corner radius (`--cosimo-radius`, 2px) rounds every framed surface and control; no other radius may appear.
- The transient parameter HUD reserves stable space but is visually silent while idle. Do not show permanent instructional text such as `Exact value appears while dragging`.
- Parameter matrices adapt to the module's actual control count; do not leave empty cells merely to preserve a fixed six-cell grid.
- On short iPhones, preserve the stable relationship surface and reduce its internal spacing before shrinking the touchable module or source graphic below a useful editing size.
- Ink owns every structural graphic: track baselines, base fills, handles, and module visualizations render black on paper. The teal accent is not a structural color; it survives only as the generic fallback where no semantic source color exists.
- Rack tile anatomy is identity row, quick label plus reserved mono value, and scrub track, beside a 44px full-height rail holding the enable cell above the dedicated reorder handle. Size the tile so the longest label/value pair ("FREQUENCY 20.00 kHz") never truncates; partial tiles at the strip edges are acceptable scroll affordances.
- Categorical selections (articulation, polarity, reducer, workspace, mode) render uppercase like all captions; mixed case is reserved for mono status strings.
- A selected parameter with no attachments simply shows an all-unlit rail — no instructions, no placeholder copy, no collapsed surface.
- Decided direction (2026-07-16, ratified in INTERACTION_MATRIX the same day): the mapping-chip row and the permanently allocated relationship-detail band are removed. One persistent source rail carries every source exactly once; the selected parameter's attachments render as chip states (lit + amount). Rail verbs: vertical scrub on a lit chip doses that mapping and focuses it — a lit chip's drag always scrubs, never carries; drag assigns from unlit chips only (assign an attached source elsewhere by selecting the destination parameter first, which unlights the chip, or through its long-press menu); tap opens the source editor; long-press manages, including "Remove from <parameter>" for lit chips. Cell Y-drag continues to dose the focused mapping. Polarity and reducer live in the source editor's target rows, not a permanent band; remove lives both there and in the lit chip's long-press menu. Rail chips keep the borderless graph-legend style (no outlines/pills).
- The finished surface must read calm despite full modulation power; the visual stress fixture may not look busy or overwhelming. Working means: black/white inversion is budgeted to a few categorical anchors (active rack module, workspace carousel, transport selections) — chip and cell focus use corner ticks only (2026-07-18: parameter-cell selection dropped its full outline for the chips' corner-tick grammar; full outlines are reserved for drag-drop feedback), never inverted slabs — permanent regions keep fixed geometry but idle content stays visually silent, a value appears in exactly one home at a time (a mapping amount lives on its chip, transient values in the HUD), and unselected parameter cells drop their X/Y caption line rather than repeating "X BASE · Y NO SOURCE" per cell.
- The prototype consumes `CosimoAdapterPort`; the in-memory mock is the test fixture, not a parallel product API. Port parameter values are normalized 0..1 and all legacy 0–100 display conversion is contained in the mobile controller (decided 2026-07-19).
- The engine route budget is 12. A 13th rail/mapping assignment changes no state, reports `ROUTE BUDGET FULL · 12 OF 12` in the transient HUD, and gives a light haptic (decided 2026-07-19).

- Module-graphic art direction (2026-07-19): the depth-stack etched ink-on-paper treatment (ui/shared/etched-ink.ts over energy fields painted from the REAL desktop geometry builders — never reimplemented graphics). The wavetable calibration is frozen provisionally in ui/shared/etched-treatment-presets.ts (WASH linework, quiet hero scan line) pending side-by-side consistency review with the filter and distortion treatments; per-graphic fine-tuning is expected, wholesale divergence is not. Grid hairlines and labels are solid vector ink drawn by the host, never dithered energy.
