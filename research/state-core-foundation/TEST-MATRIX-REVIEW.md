# Independent adversarial test matrix: plugin state

Review only, 2026-09-10. Worktree `/Users/winterfell/src/cosimo-synth`, branch `codex/plugin-state-system`. No production/test implementation or native qualification performed. This file is the reviewer-owned scope. Existing dirty work is preserved.

## Authority and review conclusion

The latest approved policy overrides `module-design-independent.md` and its earlier adversarial approval: GUI and MCP/agent edits use the same edit API and shared history; a gesture protects its control against another client (`busy`), while other fields proceed; stale expected-version edits reject; host automation bypasses gesture protection, follows the host, and creates neither history nor an echo write; shared Undo reverses the latest GUI/agent edit, and automation may subsequently override it.

The four-module architecture remains testable through intentional seams. **The matrix below includes the coordinator's frozen implementation defaults for concurrency and versions; they are requirements, not implemented proof.** In particular, the old “finish prior gesture on another key/client” behavior must fail the new tests. Passing library experiments, a hand-written channel, or `FakePatchConnection` is not qualification of Cmajor routing, native persistence, worker lifetime, or DSP installation.

This matrix names caller-visible outcomes rather than implementation algorithms. IDs are traceability references, not a request to introduce a test-management framework. Test names may combine rows when a single scenario observes all the named invariants.

## Smallest fixture and allowed proof seams

Use one ordinary plugin definition containing a scalar `gain`, a scalar `rate`, and a small immutable `curve` stored value. Give `curve` a real non-React preparation function and an ordinary event endpoint. Its declared dependency is `rate`; `gain` is unrelated. Use two actual clients (GUI and agent), one patch owner, and explicit document identities. A second stored value is needed only if testing overlap on two complex controls cannot be expressed with `gain` plus `curve`.

- **M — edit service/model:** production constructor, commands, snapshots/subscription, and receipts. Supply recording native/engine adapters through the same constructor seams production uses. Records prove requested external effects only. Do not export reducers/private atoms to drive tests.
- **C — client:** production client/binding API connected to a controllable wire implementing the actual channel interface. Deliver real serialized envelopes, including duplicates/reordering. Observe value, readiness, pending tickets, errors, history flags, and detach behavior.
- **A — channel/native-state adapter:** production service-facing adapter and real parsers with a controllable transport at its platform seam. This proves parsing and adapter policy, not native sender identity or host FIFO behavior.
- **E — engine binding:** production binding with controlled resource and transport seams. An explicit release gate can hold preparation or an acknowledgement baseline. Observe public status/completion and actual recording transport payloads.
- **B — built browser composition:** generated plugin entry, real state client, React/control binding, actual browser Cmajor connection and audio worklet. A preview-only connection or test-only Web Worker bridge is a lower-level result.
- **N — native composition:** built worker bundle in the actual Cmajor QuickJS/Patch integration and native `PatchView`/full-state entry points. Use finite test endpoints/state inspection or returned acknowledgements as public evidence; do not substitute a JavaScript map for native state.

Repository baseline uses `node:test`, `assert/strict`, `loadUIModule`, and installed `fast-check`; reuse these where appropriate. No new runner is needed solely for this work. Existing `kit/tests/test_stored_state_runtime_mirror.mjs` demonstrates an intentional recording connection seam; it does not establish native semantics. Existing `kit/tests/test_browser_preview_connection.mjs` explicitly refuses to invent DSP output. Keep that distinction.

## Frozen defaults and remaining narrow contract decisions

| ID | Distinguishing sequence | Required decision / adversarial recommendation |
| --- | --- | --- |
| D1 | Agent reads curve version 4; GUI changes only gain; agent edits curve expecting 4. Then GUI changes curve away and back before the same request. | Frozen: field-scoped monotonic versions, separate from service snapshot revision and engine target generation. Unrelated edits do not invalidate curve; an ABA change invalidates its old version. Changed host automation invalidates the observed field version as well. |
| D2 | A begins curve, edits C1; B commits gain G1; A edits C2; B ends/commits before A releases. Reverse the final pointer-up order. | Frozen: one entry per non-empty gesture, ordered by that gesture's last accepted user change, independent of pointer-up order. Automation never supplies that ordering. End/detach seals the owner's accepted work. Different-field groups may overlap. |
| D3 | A holds curve; B invokes global Undo and the latest history target is curve. Separately, latest target is unlocked gain. | Frozen simplifying default: Undo and Redo return `busy` while ANY gesture is active, including the caller's own gesture and even when the history target is another field. No stack/value/lock mutation. Caller ends its gesture first; remaining other-client gestures still block history commands. |
| D4 | A requests scalar .7 during a gesture; host automation observes .3; A requests .8; gesture ends. Undo follows. | Frozen: host observations update authoritative scalar/version without history. Recommended remaining detail: preserve initial authoritative history baseline and last accepted user request; GUI-owned gesture edits are unconditional intent, while agent edits always require expectedVersion, even when the agent owns the gesture. An agent can use the version in its previous accepted receipt; automation invalidates that version. Do not turn lock ownership into a version bypass. Define presentation of host value versus an outstanding local draft. Repeated equal observations should not advance a value version unless observation-count semantics are explicitly desired. |
| D5 | A begins curve twice; ends twice; ends curve while also gesturing gain; stale delayed end arrives after a later gesture begins on curve. | A bare `end` with only client identity is ambiguous once independent fields proceed. Carry field identity and, if the same client can reopen a field before delayed end arrives, a gesture identity. Explicitly choose repeat-begin/end behavior; never release another field/new gesture accidentally. |

These are bounded contract decisions, not permission for collaborative merge, transaction APIs, durable history, public transport epochs, or a general scheduler. One-shot edit and explicit gesture edits should share acceptance/history logic. Equal-value no-op user writes and repeated equal host observations need explicit version behavior; recommended value versions remain stable, while ABA changes do not. Agent routing must reach that same public service seam, not a second privileged state writer.

## Minimum critical vertical slices and review order

Implement and review tests for each slice before implementing its behavior. A failure due solely to a missing import may establish test scaffolding, but after production code exists require assertions to fail for the specific prohibited behavior; do not call import failure behavioral red proof. Independent review should reject weak tests before implementation and re-review the exact repaired candidate afterward.

1. **Public API and boot:** definition → generated owner → channel → client; observed scalar baseline and absent/invalid stored value; real status hydration (M1/M2/C1/A1). Begin with one scalar and curve. Get the actual native and browser attach paths working early; do not postpone the uncertain framework seam behind an entirely green fake suite.
2. **Two-client edit/history:** GUI and agent access same API; gesture edit → busy same-field rejection → other-field success → current/stale expected-version edits → shared Undo/Redo (M3–M8/C2/C6/A2). Include frozen D1–D3 defaults and the D4–D5 details in observable tests before coding concurrency.
3. **Host automation:** host parameter observation while GUI dragging and agent pending; no history/echo; Undo then next automation update; curve dependency update only for rate (M6/M7/E1). At least one native test must drive the host parameter route rather than a service test-event shortcut.
4. **Owner survival and restore:** close GUI after routed acceptance, reopen with same value/history/pending status, then actual full-state replacement with old FIFO/publication/engine work held (M10/M11/C3/A4–A6). This is a principal justification for the owner architecture and therefore a release gate, not optional stress coverage.
5. **Real engine and shutdown:** nontrivial curve preparation → actual DSP event; prove send-only evidence honestly, plus final-send supersession and teardown using the production transport (E2–E6). Add real acknowledgement only if shipping that adapter; do not introduce it solely to produce a green test.
6. **Composed interaction check:** built GUI drag → agent contention/unrelated edit → GUI Undo → host automation → close/reopen → host save/restore. Assert actual rendered/control values, receipts, host state, history, and endpoint/DSP outcome through the outer seam. Module tests do not substitute for this sequence.

## Test integrity and evidence boundaries

Use an independent small state-machine oracle only for stable policy laws (field lock exclusion, version monotonicity, unaffected-field isolation, history boundedness). Generate short valid/invalid command sequences with recorded seeds and shrink failures. Do not copy production reducer branches into a reference model and compare two identical implementations. Focused distinguishing examples above remain necessary for native temporal assumptions.

A test must become red if the implementation: restores global gesture interruption; grants agent a privileged write path; ignores expected version; increments one global edit version on unrelated controls; appends automation to history; resends host observations; accepts stale epoch effects; drops a pending receipt with an old snapshot; or marks a void send as DSP acknowledgement. Review the actual assertions against these faults. Do not add coverage percentages, passing source-string checks, or method spies as substitutes.

Required runtime gaps, until actually run:

- **Native QuickJS:** emitted bundle loads with its real globals/cancellation facilities and no test-only browser `postMessage`; module lifecycle and pending work settle on worker teardown.
- **Cmajor Patch:** actual sender identity, view-to-worker routing, serialized snapshot fence, routed-prefix detach, full-state interception, stale FIFO dispatch, and old-epoch send/publication rejection.
- **Browser Cmajor:** actual generated worker/service composition, audio-worklet fence, and returned service-host teardown. A UI-only preview and a browser Web Worker experiment cannot qualify these.
- **Host storage and gestures:** native parameter range/quantization and balanced host gesture messages; native stored-state readback; actual wrapper host-state save/restore. DAW project disk persistence requires saving and reloading a project.
- **DSP/acceptance:** actual endpoint processing/acknowledgement for any applied claim, audible change/listening for a listening claim, installed DAW discovery/interaction for a host-accepted claim. Native compile, a standalone harness, and pluginval are distinct results.

Bound scope: bundled resources are enough; no imported-asset retention, crash durability, history persistence, arbitrary multi-field atomic DSP transaction, DAW Undo integration, performance benchmark platform, or migration test suite is required by this design. Record unperformed gates plainly. No installs/shared native builds or fixed-port server mutations were performed in this review.

## Follow-up review: existing mirror full-state callback guard

Reviewed the coordinator's current diff in `kit/ui/stored-state-runtime-mirror.ts` and the two new public-seam tests in `kit/tests/test_stored_state_runtime_mirror_lifecycle.mjs`. Independently inspected the cached Cmajor `requestFullStoredState`: it registers an asynchronous single-use response callback, so holding that callback across stop/restart is a realistic external seam. The recording connection's lack of optional subscription methods does not undermine these two callback-specific assertions.

**No blocker for the narrow full-state callback repair.** The first test distinguishes stopped callback suppression from a permanently disabled mirror by verifying a new lifetime works. The second distinguishes epoch checking from a `started`-only guard, and its replay assertion catches hidden old-value replacement even if an implementation suppresses its immediate send. Neither relies on spies, private helpers, or native runtime claims. Red evidence was supplied by the coordinator; this review independently reran green evidence only.

**Remaining lifecycle defect, outside what those two tests prove:** asynchronous delivery completion at `stored-state-runtime-mirror.ts:378` and its rejection branch check only `started`, unlike the newly guarded snapshot callback. Through the production constructor: start → snapshot 10 → hold `sendRuntimeEvents` result → stop → start → snapshot 20 → resolve old delivery true. The current module keeps `deliveryInProgress` across lifetimes, so new preparation is initially blocked. Old completion then installs the old applied snapshot and builds state 20 with `previousAppliedSnapshot.state === 10`. An independent one-shot public-seam probe observed exactly those values. If old delivery never settles, the new lifetime never progresses. A restart can therefore inherit an invalid differential baseline, old failure notification, or old wait ownership.

Before claiming restart lifecycle generally fixed, add a deferred-delivery test that requires new-lifetime work to progress without releasing the old wait, then releases/rejects that old result and proves it cannot alter the new applied baseline, failure status, or delivery-in-progress state. Use the existing optional `sendRuntimeEvents` seam and inspect prepared output/delivery results. Fix ownership so old completion cannot clear a newer lifetime's active delivery. The current `Promise<boolean>` seam cannot cancel an actual already-started adapter send, so even that repair must not claim universal no-send-after-stop or native DSP cancellation. A final-send-aware production engine adapter is needed for that broader claim.
